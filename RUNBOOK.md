# Pasha Stack Runbook

This runbook is the reusable zero-to-live checklist for projects generated by `pasha-stack`.

## Interactive TUI

Run:

```bash
cd /root/projects/pasha-stack
./setup.sh
```

The TUI menu supports:

- Run preflight checks
- Create a new project
- Run full setup for the current project
- Run one setup step
- Show server status

Direct commands still work for automation.

## 0. Preflight

Run:

```bash
cd /root/projects/pasha-stack
./setup.sh preflight
```

The CLI also runs preflight automatically before `create-project` and `setup`.

Automated checklist:

- Node.js 20+
- Git
- Minimum VPS resources for a small production start: 2 vCPU, 2 GiB RAM, 20 GiB free disk
- Docker installed and daemon accessible
- GitHub CLI installed and authenticated
- GitHub scopes include `repo`, `workflow`, `read:packages`
- GitHub repository is reachable when `.pasha-stack.json` exists
- GitHub deploy and Cloudflare secrets exist when `.pasha-stack.json` exists
- `cloudflared` installed
- Cloudflare tunnel login exists at `~/.cloudflared/cert.pem`
- Cloudflare API token is valid when `CLOUDFLARE_API_TOKEN` is exported locally
- Cloudflare account and zone IDs are available when exported locally

All required checks should show green `[OK]` before continuing. For k3s + Helm production with near-zero traffic, start with at least 2 vCPU, 2 GiB RAM, and 20 GiB free disk; 2 vCPU, 4 GiB RAM, and 40+ GiB disk is more comfortable. Some Cloudflare checks are warnings unless the relevant local environment variables are exported, because GitHub secret values cannot be read back for permission verification. Keeping secrets locally is not safe; prefer `gh secret set` for storage and only export local tokens temporarily when you need verification.

## 1. Create A Project

```bash
cd /root/projects/pasha-stack
./setup.sh create-project
```

The CLI creates a new project folder under `/root/projects`, copies the starter template, renders project values, initializes Git in the new project, and starts progress tracking under `/root/projects/pasha-stack/progress/<project-slug>/`.

During project creation, choose an API published port that is not already used on the VPS. For example, if another project uses `3000`, use `3001` or another free port for the next project.

Generated layout:

```text
backend/
  api/
frontend/
  blog/
  app/
docker/
.github/workflows/
```

The API lives in `backend/api` so future backend services, like `backend/cronjob`, can be added without reshaping the project.

## 2. Install Machine Packages

Run on the VPS:

```bash
/root/projects/pasha-stack/setup.sh setup step system
```

This checks or installs Docker, Git, Node tooling, and starts Docker.

## 3. GitHub CLI Auth

```bash
gh auth login --hostname github.com --git-protocol https --web
gh auth refresh -h github.com -s workflow -s read:packages
/root/projects/pasha-stack/setup.sh setup step github
```

Required scopes:

- `repo`
- `workflow`
- `read:packages`

## 4. Docker Swarm

From the generated project directory:

```bash
/root/projects/pasha-stack/setup.sh setup step swarm
```

This initializes Docker Swarm if needed and creates the project-specific overlay network from `.pasha-stack.json`.

Example for `my-project`:

```text
my_project_app_network
```

## 5. Docker Secrets

```bash
/root/projects/pasha-stack/setup.sh setup step secrets
```

Secrets created on the VPS are project-specific:

- `<project_slug>_mongo_root_user`
- `<project_slug>_mongo_root_pass`
- `<project_slug>_mongodb_uri`

The internal Mongo connection string uses:

```bash
mongodb://<user>:<password>@<project_slug>_mongo_mongo:27017/app?authSource=admin
```

## 6. Deploy Mongo And API Stacks

```bash
/root/projects/pasha-stack/setup.sh setup step stacks
```

Expected services:

- `<project_slug>_mongo_mongo`
- `<project_slug>_api_api`

The API is published on the port chosen during `create-project`.

## 7. Deploy User

```bash
/root/projects/pasha-stack/setup.sh setup step deploy-user
```

The CLI creates a deploy user, generates an SSH key, and prints the `gh secret set` commands for:

- `SSH_HOST`
- `SSH_USER`
- `SSH_PRIVATE_KEY`
- `SSH_KNOWN_HOSTS`
- `SSH_PORT`

## 8. GHCR Login

```bash
/root/projects/pasha-stack/setup.sh setup step ghcr
```

This logs the deploy user into `ghcr.io` so the VPS can pull private package images.

## 9. Cloudflare

```bash
/root/projects/pasha-stack/setup.sh setup step cloudflare
```

The generated `cloudflared-config.yml.example` maps:

```text
API_DOMAIN -> http://127.0.0.1:<api_port>
```

## 10. Verify

```bash
/root/projects/pasha-stack/setup.sh setup step verify
curl -s http://127.0.0.1:<api_port>/health
curl -s https://YOUR_API_DOMAIN/health
```

## Progress Files

Every `create-project` and `setup` run writes:

```text
/root/projects/pasha-stack/progress/<project-slug>/progress.json
/root/projects/pasha-stack/progress/<project-slug>/logs.txt
```

Use these files to see what completed, failed, or was dry-run for a project.

## Full Setup

From the generated project directory:

```bash
/root/projects/pasha-stack/setup.sh setup full
```

Use dry-run first when you want to inspect commands:

```bash
/root/projects/pasha-stack/setup.sh setup full --dry-run
```

## Status

```bash
/root/projects/pasha-stack/setup.sh status
```
